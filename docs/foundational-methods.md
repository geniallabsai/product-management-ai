# Startup AI OS · Foundational Methods

Startup AI OS is not just a code analyzer. It is a company-building and company-transformation operating system.

It supports four primary situations:

1. A person has only an idea and needs to turn it into a company, product, MVP and operating plan.
2. A traditional company wants to digitize processes, create systems, add AI, improve operations and create growth.
3. A technology company already has product/code and needs to improve architecture, product strategy, delivery and GTM.
4. A consultant/architect needs to diagnose a business, produce a dossier and recommend a transformation roadmap.

## Method foundation

### Business model and value proposition

Use when the business, offer, audience or monetization model is unclear.

Foundation:
- Business Model Canvas
- Value Proposition Canvas
- customer profile, pains, gains, jobs to be done
- value map, products/services, pain relievers, gain creators
- pricing hypothesis and business model choices

Reference anchors:
- Strategyzer Business Model Canvas
- Strategyzer Value Proposition Canvas

### Startup and validation

Use when the idea is not validated or when a company wants to create a new digital product.

Foundation:
- hypothesis before build
- customer discovery
- interviews
- problem-solution fit
- prototype before heavy build
- MVP scope
- validation experiments
- learning loop

### Agile execution

Use when an initiative needs cadence, ownership, backlog and delivery rhythm.

Foundation:
- Scrum roles/events/artifacts when a team is building a product
- Kanban when the work is continuous and flow-oriented
- backlog, acceptance criteria and done criteria
- 7/30/90-day roadmap
- operating cadence and review rituals

Reference anchor:
- Scrum Guide 2020

### Process and operating system

Use when an existing company has manual, undocumented or inconsistent workflows.

Foundation:
- process inventory
- bottleneck mapping
- RACI / ownership
- SOPs
- service levels
- handoff points
- quality gates
- instrumentation
- automation candidates

### Solution architecture

Use when the business needs a product, internal system, automation layer or digital operating model.

Foundation:
- business architecture before software architecture
- process architecture before automation
- data architecture before AI
- system boundaries
- integrations and APIs
- build-versus-buy choices
- progressive stack: no-code → low-code → custom code → platform engineering

### Data, AI and MLOps

Use when the company wants AI agents, predictive models, automation or analytics.

Foundation:
- data inventory
- event design
- data quality
- human-in-the-loop
- model/provider strategy
- prompt governance
- evaluations
- AI risk management
- monitoring and drift
- MLOps only when ML/AI is actually used in production

Reference anchor:
- NIST AI Risk Management Framework and Generative AI Profile

### GTM and growth

Use when the company has no predictable acquisition, sales or activation system.

Foundation:
- ICP and segmentation
- positioning
- offer and PUV
- channel selection
- AARRR funnel
- growth loops
- CRM and sales stages
- activation and retention
- experiment backlog

### DevOps boundary

Startup AI OS should show product impact, version history and delivery signals. Deep runtime, CI/CD, incidents and infrastructure should become DevOps OS.

Startup AI OS includes:
- Git/version visibility
- product impact of changes
- repository/context awareness
- architecture-level risk
- technical roadmap

Future DevOps OS includes:
- CI/CD deep automation
- deployment pipelines
- runtime logs
- incidents
- observability
- environments
- cost and reliability engineering

Reference anchor:
- DORA software delivery performance metrics

## Diagnostic flow

1. Identify mode: idea, existing business, existing tech company, digital transformation, physical business.
2. Capture evidence: idea text, company context, website, social links, current tools, processes, data, repo if available.
3. Map business architecture: value creation, value delivery, value capture.
4. Map processes: current, missing, broken, automatable.
5. Map AI opportunities: assistant, classifier, recommender, predictor, automation, copilot, analyst.
6. Map stack: no-code, product, code, data, AI, DevOps boundary.
7. Build artifacts: SWOT, PUV, Value Proposition Canvas, Business Model Canvas, Eisenhower, MoSCoW, ICE/RICE, Kanban, roadmap.
8. Produce dossier: maturity, risks, opportunities, architecture, next actions.
9. Turn into execution: backlog, owners, cadence, 7/30/90 days.

## Non-negotiable product principle

Do not force the user to start with code.

If there is code, analyze it.
If there is no code, architect the business and the product to be built.
If there is no product, start with customer, process, value and GTM.
If there is no process, map the process first.
If there is no data, define what data must be captured.
If there is no AI readiness, design a human-in-the-loop path before automation.
